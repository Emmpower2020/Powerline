# داده‌های نمونه توسعه Powerline

این بسته فقط برای تست گردش کار سامانه است و **هیچ رکورد قبلی را ویرایش یا حذف نمی‌کند**.

## فایل‌ها

- `database/demo_seed.sql` — اسکریپت افزایشی؛ فقط رکوردهای جدید DEMO را وارد می‌کند.
- `database/demo_verify.sql` — چند Query برای دیدن نتیجه و کنترل روابط.
- `db/sabadgam_Powerline_demo_seeded.sql` — کپی کامل Dump اصلی به‌علاوه Seed در انتهای فایل.

فایل اصلی `db/sabadgam_Powerline.sql` دست‌نخورده باقی مانده است.

## داده‌های نمونه چه چیزی را نشان می‌دهند؟

رکوردهای دمو با شناسه‌های 90001 به بالا و کدهای `DEMO-` ساخته شده‌اند:

1. قرارداد دمو برای شهریور ۱۴۰۵
2. فهرست‌بهای کوچک دمو برای همان قرارداد، شامل بازدید پیمایشی، صعودی، پهپادی و دو قلم تعمیراتی
3. دو اکیپ دمو با اعضای موجود دیتابیس
4. قالب و آیتم‌های چک‌لیست بازدید
5. بازدیدهای تأییدشده، در حال انجام و پیش‌نویس
6. پاسخ‌های چک‌لیست و ثبت عیب برای چند دکل
7. چرخه وضعیت عیب: `new → approved → in_progress → repaired → verified`
8. دستورکارهای تعمیر با وضعیت‌های `assigned`, `in_progress`, `completed`, `verified`
9. وظایف جزئی هر دستورکار
10. اندازه‌گیری‌های صورت‌وضعیت
11. یک صورت‌وضعیت تأییدشده نمونه با اقلام بازدید و تعمیر
12. اعلان و Audit Log برای قابل مشاهده بودن جریان کار

## سناریوی نمایش‌شده

در تاریخ `2026-09-25` دو بازدید برای اکیپ بازدید برنامه‌ریزی نمونه شده‌اند:

- `DEMO-INS-1405-005` برای دکل `1260201-005` در وضعیت `in_progress`
- `DEMO-INS-1405-006` برای دکل `1260201-006` در وضعیت `draft`

همچنین عیب `DEMO-DEF-1405-005` از بازدید جاری ساخته شده و هنوز در وضعیت `new` است. برای یک عیب دیگر، دستورکار `DEMO-WO-1405-002` در حال اجراست.

برای نمایش صورت‌وضعیت نیز `DEMO-INV-1405-001` ایجاد شده است. مبلغ پایه آن `18,130,000` ریال، مالیات ۱۰ درصد `1,813,000` ریال و مبلغ نهایی `19,943,000` ریال است.

## نحوه استفاده

روی یک دیتابیس که Dump اصلی پروژه روی آن Import شده، فایل `database/demo_seed.sql` را اجرا کنید. این Seed مستقل است و لازم نیست Dump را ویرایش کنید.

برای اجرای دوباره، به دلیل استفاده از `INSERT IGNORE`، رکوردهای DEMO دوباره ساخته نمی‌شوند و داده‌های قبلی تغییر نمی‌کنند.

## نکته معماری برای توسعه بعدی

در ساختار فعلی جدول مستقل و صریحی برای **«دستورکار بازدید روزانه»** که صادرکننده آن کارشناس خط باشد وجود ندارد. Seed فعلی برای اینکه بدون تغییر Schema موجود قابل نمایش باشد، برنامه‌ریزی روزانه را با `inspections.inspection_date + crew_id + line_id + tower_id` شبیه‌سازی می‌کند.

برای نسخه بعدی بهتر است موجودیت مستقلی مانند `inspection_work_orders` یا `inspection_plans` داشته باشیم که حداقل صادرکننده، تاریخ، اکیپ، خط، محدوده دکل‌ها، اولویت، وضعیت ارسال/دریافت و زمان تأیید را نگه دارد. این موجودیت بعداً می‌تواند مبنای مستقیم اپلیکیشن اندروید سیمبان شود.

## نکته سازگاری فهرست بها

در نسخه فعلی کد، مدل جدید فهرست‌بها قابلیت ستون‌هایی مانند `parent_code` و `coefficient_kind` را پیش‌بینی کرده است، در حالی که Dump فعلی `price_list_items` این ستون‌ها را ندارد. داده دمو عمداً فقط از ستون‌های موجود در Dump استفاده می‌کند تا وارد کردن آن به ساختار فعلی امن باشد. Migration نسخه جدید فهرست‌بها را در این تغییر اجرا نکرده‌ایم.
